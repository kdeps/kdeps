# page-summarizer

A WASM workflow that summarizes the page you are looking at. `kdeps bundle
build --wasm` writes one HTML file - double-click it, no server.

```text
current tab -> bookmarklet (url + title + innerText) -> page-summarizer.html (WASM) -> OpenAI (or any cloud backend)
```

WASM cannot scrape the open tab, so the bookmarklet runs in that tab and hands
the app `url`, `title`, and `text`. Both the bookmarklet and the settings
drawer are generated by kdeps - this example only supplies the result UI.

## Build

```bash
kdeps bundle build examples/page-summarizer --wasm
```

Writes `examples/page-summarizer/page-summarizer.html`. Add `--wasm-output
server` for a static site plus nginx image instead.

## Use

1. Double-click `page-summarizer.html` (Finder / Explorer). No kdeps, no server.
2. Click the gear (top-right). Pick a backend (OpenAI, Anthropic, Groq, ...),
   a model, and paste an API key. It is stored only in this browser.
3. Drag **Send this page to page-summarizer** onto the bookmarks bar.
4. Open any article, click the bookmark. The summarizer opens (or focuses) and
   runs automatically.

You can also paste text into the box and click **Summarize**.

## What comes from kdeps vs this example

| From `kdeps bundle build --wasm` | From this example (`data/public/index.html`) |
|---|---|
| Settings drawer (backend / model / key) | The result box + a paste-and-summarize fallback |
| `KDEPS_WASM_CAPTURE: "url,title,text"` -> bookmarklet + receiver | A `kdeps:capture` listener that calls `window.kdeps.execute` |

## Layout

```
page-summarizer/
|-- kdeps.pkg.yaml
|-- workflow.yaml            # env.KDEPS_WASM_CAPTURE opts into the bookmarklet
|-- resources/
|   |-- summarize.yaml
|   `-- response.yaml
`-- data/public/index.html   # inlined into page-summarizer.html on --wasm
```
