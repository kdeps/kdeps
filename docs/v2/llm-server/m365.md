# M365 Copilot

Connects to the chat service of Microsoft 365 Copilot. This service is a
SignalR-over-WebSocket API, not a REST endpoint. kdeps runs a small local
OpenAI-compatible server in front of it (`m365` backend). As a result, it uses the same
`chat:` resource and agent-loop paths as all other providers. See [LLM Provider Reference](/llm-server/providers) for the other backends.

```yaml
# ~/.kdeps/config.yaml
llm:
  backend: m365
```

There is no `api_key` field - authentication is a signed-in Microsoft 365
account, not an API key.

**Agent mode (recommended): sign in through a real browser window.**
You can select an m365 model (`kdeps --model m365-copilot --backend m365`, or
`/model m365-copilot` in the REPL) with no cached session. The first time that
you do this, kdeps opens a visible Chrome window at the Microsoft login page.
It waits until you complete the sign-in yourself.

Use the method that your
tenant needs: password, MFA app, passkey, or SSO tile. With this method, kdeps
does not read or write a credentials file. kdeps never sees your password.
After you sign in, kdeps keeps the session in
`~/.config/kdeps/m365/token-cache.json` and refreshes it silently after that.
Each later launch goes directly to the model, with no browser window. To force
a new sign-in (to switch accounts, or to recover a revoked session), run
`/login` in the REPL.

If the Chromium driver is not installed, kdeps installs it automatically on
first use. You do not need to run `playwright install chromium`. To select a
different browser, set `CHROMIUM_PATH`. To change the location of the
persistent browser profile, set `KDEPS_M365_BROWSER_PROFILE`.

**Linux only:** downloading Chromium is not enough - it also needs a handful
of shared libraries the OS does not ship by default. On Debian/Ubuntu:

```bash
sudo apt-get install -y libnss3 libnspr4 libasound2t64
```

(On older Debian/Ubuntu releases, the package is `libasound2`, not
`libasound2t64`.) If these packages are missing, the launch error of kdeps
gives the exact package manager command for your distribution. Playwright gets
this command directly from the host. If the command and this list are
different, use the command.

**Headless hosts (CI, servers with no display): scripted `secrets.json`
fallback.** Write `~/.config/kdeps/m365/secrets.json` yourself before running
kdeps:

```json
// ~/.config/kdeps/m365/secrets.json
{
  "email": "you@yourtenant.com",
  "password": "your-password",
  "mfaSecret": "your-TOTP-seed"
}
```

`mfaSecret` is the TOTP seed (the same secret that you scan into an
authenticator app). It is not a one-time code. kdeps makes the codes from it.

For this reason, your account must have authenticator-app MFA (not only push or SMS). When
this file exists, kdeps does not open a visible window. It uses a headless
Chromium browser to complete the Azure AD login form with those credentials.
It keeps the refresh token in the cache in the same way. The `chat:` resource
of workflow mode has no terminal or display for a prompt. For this reason, it always needs
this file before it runs.

Override paths with `KDEPS_M365_CACHE_FILE`, `KDEPS_M365_SECRETS_FILE`, and
`KDEPS_M365_BROWSER_PROFILE`.

For most tones, tool calls go through a Copilot Studio agent that kdeps
provisions automatically. Claude tones have no agent, to keep the tone. An
agent forces GPT-5. One exception is `Claude_Opus`, which keeps the agent
because its tool calls through the agent are reliable. `gpt-6-think-deeper`
has no agent, because its agent route does not serve. By default, the Sol
tones (`gpt-6-sol`, `gpt-6.1-sol`) have no agent.

Their agent route serves only
on a premium account, and a token does not identify a premium account. To
force the behavior, use `KDEPS_M365_FORCE_AGENT=1` (always attach) or
`KDEPS_M365_FORCE_AGENT=0` (never attach).

Each chat request also has a `scenario` and `licenseType` query pair. This
pair sets the tones that the service serves. kdeps requests tones that need an
entitlement (`Claude_Opus`, `claude-sonnet-5`, `claude-sonnet-5.5`,
`gpt-6-think-deeper`) with the paid scenario (`OfficeWebPaidCopilot`,
`Premium`). All other models use the included scenario
(`OfficeWebIncludedCopilot`, `Starter`).

With the included scenario, a tone that needs an entitlement gives the standard
BotConnection apology, not a reply. For this reason, kdeps never sends such a tone there.
`claude-opus-4.8` and `claude-opus-4.5` are the exceptions in the Opus family.
They serve with the included scenario, so they stay there. To override the
fields, set `KDEPS_M365_SCENARIO` and `KDEPS_M365_LICENSE_TYPE`.

M365 models (especially Claude tones) have a built-in code interpreter.
Sometimes they use it, not the fenced kdeps tools. Its sandbox is empty, so
each result is empty.

 The model then reports "NO CONTENT AVAILABLE" or says
that it cannot read files. The system preamble tells the model to use only the
kdeps tools. If the model makes this mistake again, reply
`use the kdeps tools, not your own`. The model then recovers.

The provisioned Copilot agent gets an instruction about tool calls. kdeps, not
the code interpreter of the model, parses one matched `<invoke>` block in the
reply at runtime and runs it. An `<invoke>` block in a markdown fence is never
a call. The tags must be outside the fence.

kdeps recovers calls from free text. For this reason, an answer that *quotes* that syntax
(or names a tool, like "read the plan file, limit 100 lines") can look like an
action. kdeps keeps such a reply as text in three conditions: the recovered
call does not have a necessary parameter, it repeats a call from this turn, or
it is in a long prose answer. As a result, a final summary that mentions tool names
shows in full. It does not leave some fragments before the prompt.

Reasoning-tone models (`think-deeper`, `*-think-deeper`) stream their
chain-of-thought summary as live reasoning feedback. This is the same as native
extended-thinking models. The agent-loop REPL shows it automatically (thinking
is on by default). For direct API use, it is in `reasoning_content` in the raw
OpenAI-compatible response.

When the Copilot upstream fails mid-stream, the local server can only report it
to a plain OpenAI-compatible client as a content delta: `[m365 error: ...]`.
kdeps itself treats that marker as an upstream failure. The agent loop tries a
dropped connection again. After the last retry, kdeps reports the error. It
does not save the error as the answer of the assistant.

Service throttling arrives in the same way, as the plain-text apology "We're
temporarily unable to respond to this volume of requests." kdeps treats that
message as a rate-limit error. The agent loop waits and tries again. It does
not save the apology as the reply.

| Model | Description |
|-------|-------------|
| `m365-copilot` | Default - service picks the model |
| `quick` | Fast, lower-latency responses (GPT-5.5 chat tone) |
| `think-deeper` | Extended reasoning (GPT-5.5 reasoning tone) |
| `claude` | Alias for `claude-sonnet` |
| `claude-sonnet` | Claude Sonnet via M365 (`-4.5`, `-4.6` variants) |
| `claude-sonnet-5` | Claude Sonnet 5 - paid scenario |
| `claude-sonnet-5.5` | Claude Sonnet 5.5 - paid scenario |
| `claude-sonnet-think-deeper` | Sonnet with extended reasoning |
| `claude-opus` | Claude Opus via M365 - paid scenario |
| `claude-opus-4.5`, `claude-opus-4.8` | Opus on the included scenario |
| `claude-opus-5`, `claude-opus-5.5` | Opus 5 family - paid scenario |
| `gpt-6-think-deeper` | GPT-6 reasoning - agent-less, paid scenario |
| `gpt-6-sol`, `gpt-6.1-sol` | GPT-6 Sol reasoning - agent-less by default |
| `gpt-5.6` | GPT-5.6, `-quick`/`-think-deeper` variants |
| `gpt-5.5`, `gpt-5.4`, `gpt-5.3`, `gpt-5.2` | GPT-5.x family, `-quick`/`-think-deeper` variants |

An unrecognized `claude-*` name keeps its model family instead of falling back
to GPT: anything containing `opus` resolves to the Opus tone, other `claude*`
names to Sonnet (or Sonnet 5 for a `sonnet-5` name that is not 5.5).

## Standalone proxy

`kdeps m365 proxy` runs the OpenAI-compatible server on a fixed port with CORS
open, so any OpenAI client (Cursor, LiteLLM, curl, another kdeps host) can call
it:

```bash
kdeps m365 proxy               # http://127.0.0.1:11435/v1
kdeps m365 proxy --port 8080 --host 0.0.0.0
```

The first request opens a browser to sign in (or pre-seed
`~/.config/kdeps/m365/secrets.json`). Point the client at `http://<host>:<port>/v1`.
